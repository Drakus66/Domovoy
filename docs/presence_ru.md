# Присутствие (Epic 3D)

Присутствие в Домовом — **платформенный сигнал**: «кто дома» перестаёт быть побочным
эффектом датчиков движения и становится первоклассной сущностью, из которой питаются
режим дома (1G), правила, сцены и (в перспективе) охрана (4B). Этот эпик добавляет
**слой источников** под уже существующий контур режимов — то, чего не хватало после
удаления жёстко закодированного `PresenceMonitor`: не логику, а **данные о присутствии**.

## Модель

- **Жилец (`Resident`)** — отслеживаемый член семьи (коллекция `residents`). Тонкая
  запись: имя, необязательная связка с пользователем 2E (`UserId`), идентификатор
  источника геолокации (`OwnTracksId`), флаг участия (`TrackingEnabled`). Гостя можно
  отслеживать без учётной записи.
- **Устройство-персона** — на каждого жильца платформа публикует виртуальное устройство
  (`AdapterSource=System`, `Model=system/person`, архетип `person`) с капабилити
  `presence` (bool) и, при наличии в отчёте, `battery`. Оно показывается на дашборде и
  работает в правилах/сценах как любой датчик.
- **Устройство-агрегат «Occupancy»** (`system/presence`, архетип `presence`) с капабилити
  `anyone_home` (bool) и `home_count` (number). Именно его «Кто-то дома» пользователь
  привязывает ко входу блока `presence_mode` (1G), чтобы переключать режим дома по
  присутствию.

Присутствие **не персистится** (как сигнал `power_source` 3C-LM и в отличие от режима
дома): это живой сигнал, восстанавливаемый по мере поступления отчётов; после рестарта —
«неизвестно/ушёл», пока источник не отчитается.

## Источник v1: геолокация, совместимая с OwnTracks

[OwnTracks](https://owntracks.org) — приватное, дружелюбное к self-hosting приложение,
шлющее один и тот же JSON и по HTTP, и по MQTT. v1 принимает **HTTP-режим**, поэтому
не нужно выставлять наружу брокер:

```
POST {origin}/api/presence/owntracks?user=<OwnTracksId>
```

- В настройках приложения OwnTracks выберите режим **HTTP** и укажите этот URL. Значение
  `user` (или `tid`/`topic` в самом payload) сопоставляется с `OwnTracksId` жильца
  (без учёта регистра). Готовый адрес для копирования показывается в диалоге жильца.
- Сообщения `location` несут координаты → **серверная геозона**; сообщения `transition`
  с регионом `home` (enter/leave) — доверенный быстрый путь, минующий расчёт расстояния.
- Эндпоинт **анонимный** (OwnTracks не носит наш JWT). Если задан **токен приёма**, он
  требуется как `?key=` или заголовок `X-Presence-Token` — задайте его, когда эндпоинт
  доступен вне локальной сети, чтобы присутствие нельзя было подделать.

### Серверная геозона

Дома/ушёл решается на сервере, а не на телефоне: позиция в пределах `HomeRadiusMeters`
от участка (2K) = **дома**. **Приход учитывается сразу**; **уход выжидает**
`AwayGraceSeconds`, гася джиттер GPS и краткий выход за порог, чтобы дом не «прыгал» в
Away и обратно. Жилец, который ушёл и перестал отчитываться, флипается по таймеру
периодического тика (grace-окно).

Настройки — на странице **«Присутствие»** (`/presence`): радиус, задержка ухода, токен
приёма. Дефолты: 150 м, 180 с, без токена.

## Дальнейшие слои источников (не в v1)

Контракт `PresenceReportedV1` источник-агностичен (координаты **или** явный
enter/leave), поэтому следующие слои подключаются без изменения ядра:

1. **Комнатный уровень (Wi-Fi/BLE)** — ESPresense/Bermuda через bluetooth-proxy ESPHome
   (плагин 1C).
2. **mmWave-зоны** — Aqara FP2/FP300 уже подключаемы по Zigbee2MQTT (публикуют `occupancy`).

## Как это питает режим дома (1G)

Логика режимов не меняется. Агрегат `anyone_home` — обычный boolean на устройстве, он
привязывается ко входу `presence_a` блока `presence_mode`, который и переключает режим
(любой датчик true → home; тишина дольше задержки → away, с guard ручных Night/Vacation).
То есть 3D даёт **источник**, а не политику.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET/POST/PUT/DELETE | `/api/residents` | CRUD ростера жильцов (DbGateway) |
| GET/PUT | `/api/settings/presence` | Настройки геозоны/токена (singleton) |
| POST | `/api/presence/owntracks` | Приём отчёта OwnTracks (анонимный) |
| GET | `/api/presence/status` | Живой статус: агрегат + по жильцам (AutomationService) |
