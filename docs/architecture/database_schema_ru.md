# Схема базы данных и связи Domovoy

## Обзор

Domovoy использует шлюзовую архитектуру (Gateway Pattern) для работы с базой данных. DbGateway действует как централизованный сервис, отвечающий за все взаимодействия с базой данных, в то время как остальные сервисы коммуницируют с ним через API эндпоинты и сообщения на шине. Этот подход обеспечивает согласованность данных и изоляцию сервисов от деталей реализации доступа к данным.

## Архитектура доступа к данным

### Gateway Pattern (Шлюз данных)

В Domovoy используется шаблон Gateway для абстрагирования логики работы с базой данных:

- **DbGateway** выступает как единая точка взаимодействия с базой данных
- Остальные сервисы не имеют прямого доступа к базе данных
- Сервисы запрашивают данные через REST API DbGateway или через сообщения шины
- DbGateway самостоятельно отслеживает сообщения на шине и обновляет базу данных

### Технологии баз данных

Система использует MongoDB в качестве основного хранилища данных:

- **Основное хранилище**: MongoDB для хранения информации об устройствах
- **Данные временных рядов**: MongoDB с индексацией по времени для сенсорных данных
- **Кэширование**: Redis для кэширования часто запрашиваемых данных

## Поток данных

1. **Регистрация устройств**: 
   - Сервисы отправляют события регистрации устройств на шину сообщений
   - DbGateway перехватывает эти события и создает записи в базе данных

2. **Обновление состояния**: 
   - Устройства публикуют изменения состояния через шину сообщений
   - DbGateway подписан на эти события и обновляет состояние в базе данных
   - Сервисы могут запрашивать текущее состояние через API DbGateway

3. **Сенсорные данные**: 
   - Показания датчиков публикуются на шине сообщений
   - DbGateway сохраняет их в коллекции SensorReadings с временными метками
   - Историческая аналитика осуществляется через запросы к DbGateway

4. **Команды пользователя**: 
   - Команды пользователя регистрируются в коллекции DeviceCommand для аудита
   - DbGateway логирует результат выполнения команд

## Паттерны доступа к данным

- **Сервисы не имеют прямого доступа к базе данных**
- **DbGateway**: 
  - Предоставляет REST API для запроса данных устройств
  - Обрабатывает события с шины сообщений для актуализации данных
  - Реализует все операции создания, чтения, обновления и удаления (CRUD)
  - Поддерживает фильтрацию по типам устройств и локациям

- **DeviceService**: Запрашивает информацию через API DbGateway
- **LightService**: Запрашивает данные светильников через API DbGateway
- **SensorService**: Получает данные датчиков через API DbGateway

## Миграция данных и версионирование

Управление схемой базы данных централизовано в DbGateway:

1. Изменения схемы контролируются только в DbGateway
2. Использование MongoDB позволяет гибко эволюционировать схему
3. Контракты API DbGateway поддерживают обратную совместимость
4. Версионирование API используется для критических изменений

## Особенности производительности

- Индексы по часто запрашиваемым полям (DeviceId, Location, Type, Timestamp)
- Хранение состояний устройств в JSON-формате для гибкости
- Ротация исторических данных на основе политик хранения
- API для пагинации больших наборов данных
- Кэширование частых запросов в Redis
