## 1. Принципы выбора

1. **Ethernet > Wi-Fi.** Проводной узел не зависит от качества Wi-Fi-покрытия, не отваливается при перезагрузке
   точки доступа и не участвует в борьбе за эфир. Для стационарных датчиков/исполнителей — всегда кабель, если
   он физически возможен.
2. **PoE = питание + сеть одним кабелем.** Нет розетки у места установки — не проблема; PoE-коммутатор на ИБП
   держит все узлы при пропадании питания. Прямо поддерживает принцип-инвариант «локально без внешней сети».
3. **Первоклассная поддержка в ESPHome** (или прошивка Domovoy Native). Никаких вендорских облаков и
   закрытых прошивок в критическом пути.
4. **Массовость и повторяемость.** Плата/датчик должны быть покупаемы годами, желательно open hardware —
   чтобы рекомендация не протухала.

## 2. Узлы: платы ESP32 с Ethernet + PoE

### 2.1. Основная рекомендация — Olimex ESP32-POE-ISO

[Olimex ESP32-POE-ISO](https://www.olimex.com/Products/IoT/ESP32/ESP32-POE-ISO/open-source-hardware) — эталонная
плата для стационарных узлов ESPHome (ориентир €22–28):

- Ethernet 100 Мбит (PHY LAN8720) + **PoE 802.3af**, open hardware, выпускается годами;
- **3000 В гальваническая развязка** от PoE-питания — можно безопасно подключать USB для прошивки/отладки,
  не отключая Ethernet-кабель;
- штатно поддержана в ESPHome; разъём UEXT (UART/I²C/SPI) удобен для датчиков;
- варианты с WROOM/WROVER (WROVER — если нужен PSRAM).

⚠️ У более дешёвой **ESP32-POE (без -ISO)** развязки нет: одновременное подключение USB и PoE-питания опасно
для платы и компьютера. Для узлов «прошил и забыл» она допустима, но по умолчанию брать **-ISO**.

Базовый конфиг Ethernet для ESPHome (вместо `wifi:`), остальное — по [`esphome_setup_ru.md`](esphome_setup_ru.md):

```yaml
ethernet:
  type: LAN8720
  mdc_pin: GPIO23
  mdio_pin: GPIO18
  clk_mode: GPIO17_OUT
  phy_addr: 0
  power_pin: GPIO12
```

### 2.2. Альтернативы

| Плата | Чем интересна | Оговорки |
|---|---|---|
| [wESP32](https://wesp32.com/) (Silicognition) | PoE-бюджет до 13 Вт — хватает и на нагрузку (реле, LED); open hardware | Дороже (~$40+); в новых ревизиях PHY RTL8201 (`type: RTL8201`) |
| LILYGO T-ETH-Lite (ESP32-S3) | Современный ESP32-S3, Ethernet W5500 (SPI, `type: W5500`) | PoE — отдельным модулем-шилдом; меньше истории эксплуатации |
| [M5Stack PoESP32 Unit](https://shop.m5stack.com/products/esp32-ethernet-unit-with-poe) | Готовый корпус, компактный, PoE | GPIO наружу только через Grove-разъём — фактически 1 датчик на узел |
| EST-PoE-32 | DIN-совместимый форм-фактор | Менее распространена, дороже Olimex |

### 2.3. Когда Wi-Fi допустим

Мобильные/временные узлы и места, куда кабель не проложить: обычный `esp32dev`-класс (DevKitC и клоны).
Правило: Wi-Fi-узел не должен нести критичные функции безопасного пола (протечка/дым/CO₂-защита) — для них
кабель или Zigbee-датчик с батарейным питанием и штатным мониторингом живости.

## 3. Датчики CO₂

### 3.1. Почему НЕ MH-Z19B/C

Исторический дефолт DIY-рынка, но брать его больше не стоит:

- **рынок наводнён клонами/подделками** MH-Z19B с непредсказуемой точностью (задокументировано, см.
  [разбор eMariete](https://emariete.com/en/sensors-co2-mh-z19b-false/)) — лотерея при каждой покупке;
- дрейф и скачки из-за агрессивной автокалибровки (ABC), заявленная точность ±50 ppm + 5 % — хуже всех
  рекомендованных ниже;
- капризен к питанию (просадки 5 В → выбросы показаний).

### 3.2. Рекомендованные модели

| Датчик | Технология | Интерфейс | Точность | Ориентир цены | Ниша |
|---|---|---|---|---|---|
| **Senseair S8 LP** | NDIR, 1-канальный | UART (Modbus) | ±40 ppm + 3 % | ~$25–35 | Максимальная долговременная стабильность: заводская калибровка, заявленный ресурс >15 лет, «поставил и забыл». Выбор для узлов безопасного пола |
| **Sensirion SCD41** (SCD40) | фотоакустический NDIR | I²C | ±(40 ppm + 5 %) | ~$20–30 (модуль) | Компактный, заодно даёт температуру и влажность; SCD41 — расширенный диапазон и low-power-режимы |
| **Sensirion SCD30** | NDIR, 2-канальный | I²C | ±(30 ppm + 3 %) | ~$50–60 | Самый точный из троих (двухлучевой канал компенсирует старение); крупнее и дороже |

Итог восстановленного анализа: **дефолт — Senseair S8 LP** (стабильнее и предсказуемее MH-Z19 при той же цене),
**SCD41 — когда нужен компактный комбинированный датчик** (CO₂+T+RH одним корпусом на I²C),
**SCD30 — когда важна точность** (например, референсный датчик для сверки остальных).

### 3.3. Подключение к ESP32 (ESPHome)

`device_class: carbon_dioxide` автоматически маппится адаптером в capability `carbon_dioxide` — датчик
попадает в правила и безопасный пол (protected-правило «CO₂ > порога → вентиляция»,
см. [план развёртывания §3.2.1](deployment_plan_ru.md)).

**Senseair S8** на UEXT-разъёме Olimex ESP32-POE(-ISO) (питание 4.5–5.25 В, стабильное):

```yaml
uart:
  tx_pin: GPIO4    # → RX датчика
  rx_pin: GPIO36   # ← TX датчика
  baud_rate: 9600

sensor:
  - platform: senseair
    co2:
      name: "CO2"
      device_class: carbon_dioxide
```

**SCD41/SCD40/SCD30** по I²C (тот же UEXT: SDA=GPIO13, SCL=GPIO16):

```yaml
i2c:
  sda: GPIO13
  scl: GPIO16

sensor:
  - platform: scd4x        # для SCD30 — platform: scd30
    co2:
      name: "CO2"
      device_class: carbon_dioxide
    temperature:
      name: "Temperature"
    humidity:
      name: "Humidity"
```

### 3.4. Эксплуатационные заметки

- **Автокалибровка (ABC/ASC)** у всех трёх опирается на предположение «помещение хотя бы иногда проветривается
  до уличных ~420 ppm». В жилых комнатах это обычно верно — оставить включённой; в постоянно занятых/герметичных
  помещениях — выключить и раз в сезон делать ручную калибровку на улице/у открытого окна.
- **Размещение:** на высоте дыхания (1–1.5 м), не над источниками тепла, не в прямом потоке вентиляции,
  не на солнце. SCD4x чувствителен к самонагреву — в тесном корпусе показания T завышаются (компенсировать
  `temperature_offset`).
- **Питание:** S8 требует честных 5 В ≥300 мА пиками; при PoE-плате это решается штатно. SCD4x работает от 3.3 В.
